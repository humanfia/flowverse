# Lane collaboration

Lane 1 alone edits the original source. Lanes 2 and 3 edit private snapshots and publish explicit,
reconstructable artifact files. Read the repository and current mission at the start of every fresh
turn; leave coherent files and factual evidence for the alternating partner.

Use `progress` for material unfinished work, `deliverable_ready` for a validated reconstructable
package, `no_result` for an exhausted falsifiable direction, and `blocked` only for a concrete
blocker. All lanes may attach one task-evaluator-accepted local candidate. Inspect the shared
leaderboard, never submit estimates, and never mutate a published candidate package.

The audit policy may deliberately suppress an outcome audit. In that case, use the retained
`last_suppressed_outcome` in the mission state to avoid repeating settled work and choose a useful
within-mission continuation.
